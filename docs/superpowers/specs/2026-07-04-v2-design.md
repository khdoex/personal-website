- Tech: Framer Motion (already a dependency). No GSAP, no CSS scroll-timeline (browser support).

## Architecture

### Motion primitives - `components/motion/`

- `Reveal.tsx` (client): viewport-entry rise (opacity 0->1, y 14->0), reversible (`whileInView`, `once: false`, amount 0.25), optional `delay`. Honors `useReducedMotion` by rendering static.
- `Stagger.tsx` (client): parent orchestrator, `staggerChildren` ~70ms; children use a shared item variant. Same reduced-motion guard.
- Scenes are bespoke per location (no generic Scrub component - YAGNI): the about-page portrait parallax lives in the about page's client component; figure assembly lives in the figure components.
- The CSS `.reveal` class stays in globals.css (resume page keeps using it); home/projects/blog swap to the components.

### Pages

- `app/page.tsx`: hero + links only (currently section removed -> about). Wrapped in Stagger/Reveal.
- `app/about/page.tsx` (NEW): server shell + `AboutHero` client component. Portrait `public/images/kaan.png` masked via CSS radial-gradient mask on the right, desaturated (`saturate(0.75)`), subtle scroll parallax (portrait translates slower than text, via `useScroll` + `useTransform`). Story: 3-4 short paragraphs in Kaan's voice (drafted from his voice-game answers: physics background, the padova detour, interp thesis, SCL day job). Then `currently` list (same data, moved from home) with Reveal cascade.
- `components/Navigation.tsx`: navItems gains `{ href: '/about', label: 'about' }` (order: blog, projects, about, resume). Homepage hero links gain `about`.
- `app/projects/page.tsx` + `app/blog/page.tsx`: `.reveal` classes -> `Reveal`/`Stagger` components. No layout changes.
- `app/resume/page.tsx`: untouched (CSS reveal remains).

### Blog medium

- Config: consolidate to ONE `next.config.mjs` using `@next/mdx` (`createMDX`), `images.unoptimized: true` (Cloudflare), delete dead `next.config.ts`. Root `mdx-components.tsx` (required by @next/mdx, returns defaults; custom components are imported inside each .mdx file).
- Rich posts: `posts/rich/<slug>.mdx`, each exports `meta = { title, date, slug, readingTime }`. Registry `lib/rich-posts.ts` statically imports each mdx module and maps slug -> { Component, meta }. Authoring a future post = drop an .mdx + one registry line.
- `lib/posts.ts`: `getAllPosts()` merges markdown/html posts with rich-post metas (same PostData shape, `rich: true` flag). `app/blog/[slug]/page.tsx`: if slug is in the registry, render `<Component />` inside the same article/prose shell (no `dangerouslySetInnerHTML` path); else existing pipeline. Rich posts use `max-w-2xl` article like md posts; ReadingProgress stays.
- MDX components - `components/mdx/`:
  - `ScrollFigure.tsx` (client): figure wrapper owning a ref + `useScroll` progress (offset `["start 0.85", "start 0.35"]`), provides progress via React context; renders `<figure>` + mono `<figcaption>` ("fig N · caption", muted, amber number).
  - `Bars.tsx` (client): consumes ScrollFigure context; horizontal bars (label + value 0..1) whose widths grow from the scroll progress, staggered per-index via `useTransform` ranges. Accent gradient fill.
  - `ConnectDots.tsx` (client): consumes context; SVG dots + `motion.path` with `pathLength` bound to progress (lines draw as you scroll).
  - `Widget.tsx` (client): terminal-card frame - surface bg, border, mono title bar (`~/name`) - around arbitrary interactive children.
  - `MarginNote.tsx`: >=xl: absolutely positioned note in the right gutter next to the paragraph; <xl: inline surface-tinted aside. Mono, small, muted. No numbering (YAGNI).
  - `RefusalToy.tsx` (client): the demo widget. SVG scatter of two clusters (harmless=accent, harmful=amber), an arrow for the refusal direction, a slider for ablation strength; harmful points slide along the direction as you drag, an output line crossfades between "i can't help with that" and a compliant answer. Self-contained toy data, no deps.
- Demo post: `posts/rich/inside-the-medium.mdx` - short post in Kaan's voice about the new medium itself, using every component once (MarginNote, ScrollFigure+Bars, ScrollFigure+ConnectDots, Widget+RefusalToy). Copy follows kaans-voice; lowercase title.

### Accessibility / performance

- Every motion component checks `useReducedMotion()` and renders final-state static when set.
- All motion components are leaf client components; pages stay server components.
- No new dependencies at all.
